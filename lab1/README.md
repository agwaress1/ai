# Lab 1 — Введение в машинное обучение и подготовка данных

## Описание проекта

Учебный проект по курсу Data Science: полный цикл анализа данных и построения модели бинарной классификации — от загрузки исходных данных и проведения разведочного анализа до предобработки признаков, обучения модели и формирования бизнес-вывода.

В работе исследуется задача прогнозирования увольнения сотрудников компании на основе их демографических характеристик, условий работы, уровня дохода, должности и других показателей.

В проекте реализованы EDA, группировка данных, визуализация, Feature Engineering с использованием One-Hot Encoding, масштабирование признаков и обучение модели `RandomForestClassifier`.

## Датасет

**IBM HR Analytics Employee Attrition & Performance** (Kaggle):  
https://www.kaggle.com/datasets/pavansubhasht/ibm-hr-analytics-employee-attrition-performance

Датасет содержит информацию о сотрудниках компании и факторах, которые могут быть связаны с их увольнением.

Целевая переменная `Attrition` показывает, покинул ли сотрудник компанию (`Yes` / `No`).

### Основные характеристики данных

- **Размер:** 1470 строк, 35 столбцов
- **Целевая переменная:** `Attrition` — факт увольнения сотрудника (`Yes` / `No`)
- **Тип задачи:** бинарная классификация
- **Признаки:** возраст, должность, образование, семейное положение, доход, стаж работы, удовлетворённость работой и другие характеристики сотрудника
- **Категориальные признаки:** `BusinessTravel`, `Department`, `EducationField`, `Gender`, `JobRole`, `MaritalStatus`, `OverTime` и другие
- **Числовые признаки:** `Age`, `DailyRate`, `DistanceFromHome`, `MonthlyIncome`, `YearsAtCompany`, `YearsInCurrentRole` и другие

## Бизнес-задача

Предсказать, уволится ли сотрудник компании, используя доступные сведения о нём и условиях его работы.

Задача представляет собой бинарную классификацию:

- `0` — сотрудник остался в компании;
- `1` — сотрудник уволился.

Практическая ценность модели заключается в возможности заранее выявлять сотрудников с повышенной вероятностью увольнения. Это позволяет HR-отделу анализировать потенциальные причины текучести кадров и принимать более обоснованные решения по удержанию сотрудников.

## Ход работы

1. **Загрузка и первичный анализ** — чтение CSV-файла с помощью Pandas, проверка размерности (`shape`), первых строк (`head`) и типов данных (`info`).

2. **EDA** — исследование структуры данных и зависимостей между признаками. Используется `groupby` для сравнения показателей сотрудников в различных категориях.

3. **Визуализация** — построение `boxplot` для анализа зависимости `Attrition` от числового признака. В обязательном порядке формируется краткий аналитический вывод по графику.

4. **Feature Engineering** — категориальные признаки преобразуются в числовой формат с помощью One-Hot Encoding (`pd.get_dummies` с параметром `drop_first=True`).

5. **Разделение данных** — формируются `X` и `y`. Данные разделяются на обучающую и тестовую выборки с использованием `train_test_split` и параметра `stratify`.

6. **Масштабирование** — числовые признаки масштабируются с помощью `StandardScaler`. Скалер обучается только на Train-выборке для предотвращения утечки данных.

7. **Обучение модели** — используется алгоритм `RandomForestClassifier`.

8. **Оценка модели** — выполняется прогноз с помощью `predict`, после чего качество оценивается метрикой `accuracy_score`.

## Бизнес-вывод

Построенная модель может использоваться как вспомогательный инструмент для анализа риска увольнения сотрудников.

Полученные прогнозы позволяют выделять группы сотрудников, для которых модель обнаруживает более высокую вероятность ухода. HR-специалисты могут дополнительно исследовать такие случаи и анализировать факторы, связанные с текучестью кадров.

При этом результат модели следует рассматривать как инструмент поддержки анализа, а не как единственное основание для принятия кадровых решений.

## Контрольные вопросы

### 1. В чем главное отличие между парадигмами «Обучение с учителем» и «Обучение без учителя»?

**Обучение с учителем (Supervised Learning)** использует данные, для которых заранее известна целевая переменная. Модель учится находить зависимость между признаками и известным правильным ответом.

**Обучение без учителя (Unsupervised Learning)** работает с данными без заранее заданной целевой переменной. Алгоритм самостоятельно ищет закономерности и структуру в данных, например выделяет группы похожих объектов.

### 2. Какую фундаментальную проблему однослойного перцептрона описали Минский и Паперт в 1969 году?

Минский и Паперт показали ограничения однослойного перцептрона при решении некоторых задач, в частности задач, которые не являются линейно разделимыми. Классическим примером является задача XOR.

### 3. Зачем при подготовке текстовых данных нужно применять One-Hot Encoding вместо простого присвоения категориальным признакам чисел?

Если присвоить категориям числа, например `0`, `1` и `2`, модель может интерпретировать эти значения как упорядоченные величины. Однако категории могут не иметь такого порядка.

One-Hot Encoding создаёт отдельную бинарную колонку для каждой категории, благодаря чему категориальные значения преобразуются в числовой формат без искусственного порядка между ними.

### 4. Почему нельзя производить вычисление параметров `StandardScaler` на всей выборке до её разбиения на Train и Test?

Если выполнить `fit` на всей выборке, параметры масштабирования будут рассчитаны в том числе с использованием тестовых данных.

Это приводит к утечке информации из Test в Train и делает оценку качества модели менее корректной. Поэтому сначала данные разделяются на Train и Test, после чего `StandardScaler` обучается только на Train.
